# 团队设计

**日期：** 2026-08-31
**状态：** 已批准，待编写实现计划

## 背景

当前设置页把 `driver === "multica"` 的实例作为供应商实例展示。这样会把 Leader、Builder、Reviewer 等团队执行角色与 Codex、Claude、BYOK 等模型供应商混在同一个列表中，用户无法从信息架构上区分“模型来源”和“团队执行运行时”。文档中的 `multica` 仅是兼容既有配置的内部驱动标识，不作为用户可见名称。

团队运行时配置已经存在于 `ServerSettings.providerInstances`，并且前端已有对应配置模型、校验逻辑、组合编队、委派和 BYOK 模型适配器能力。本次只调整界面归属和团队配置入口，不迁移后端存储合同。

## 目标

1. 供应商设置页不再显示任何团队运行时实例。
2. 在设置侧边栏提供明确的“团队”入口。
3. 团队集中展示和管理团队运行时、Agent 编队及编队运行能力。
4. Agent 编队成员可以使用已经配置的 BYOK Agent 模型。
5. 既有团队运行时配置、启用状态、环境变量脱敏占位和路由映射保持兼容。

## 非目标

- 不拆分或重命名 `ServerSettings.providerInstances` 后端存储合同。
- 不改变团队运行时的 HTTP、WebSocket、MCP、心跳、任务状态或协议。
- 不新增独立数据库表或迁移脚本。
- 不把团队运行时的凭据写入新的明文存储位置。
- 不把现有团队运行时能力重新实现一遍。

## 信息架构

### 侧边栏

复用现有 `/settings/squads` 路由，将侧边栏显示名称从“Agent 编队”调整为“团队”。保留该路由，避免旧书签或内部链接失效。

团队页面按以下顺序组织：

1. 团队运行时：列出全部团队运行时实例，支持新增、编辑、启用或禁用，并显示配置有效性和运行能力。
2. Agent 编队：复用现有编队创建、编辑、归档能力。
3. 编队运行：复用现有编队运行和结果查看能力。
4. 团队运行控制：复用现有组合运行控制中心。

“委派”和“BYOK”继续保留为独立设置入口。BYOK 页面仍是模型适配器和委派全局配置的来源，团队只消费可用的 BYOK Agent 模型。

### 供应商页

供应商实例列表只保留真正的 Provider/模型来源实例。构建实例行时过滤 `driver === "multica"`，并防止后续未知驱动兜底分支再次把团队运行时实例加回列表。现有其他未知驱动仍按照当前兼容行为保留。

新增供应商向导当前没有团队运行时选项，本次继续保持这一边界；不通过供应商向导创建团队运行时。

## 配置与数据流

```text
ServerSettings.providerInstances
        |
        +-- driver !== "multica" --> settings/providers
        |
        +-- driver === "multica" --> settings/squads（团队）
                                      |
                                      +--> 团队运行时 settings logic/model/validation
                                      +--> Agent 编队成员模型选择
```

### 团队运行时

- 从现有 `providerInstances` 中筛选 `driver === "multica"`。
- 使用已有 `formFromMulticaRuntimeInstance` 生成编辑草稿。
- 使用已有 `validateMulticaRuntimeDraft` 做保存前校验。
- 保存时只更新原有 `providerInstances` 映射，并保留非团队运行时实例、其他设置和 Secret 脱敏占位。
- 实例 ID 变更时沿用现有 `originalInstanceId` 语义，避免已保存敏感值因改名丢失。
- 没有有效配置的实例显示不可用状态和校验原因，不阻塞其他团队配置的查看。

### BYOK Agent 模型

- 从当前已配置的 BYOK provider instances 读取 adapters。
- 在 Agent 编队成员的模型字段中优先提供可选的 BYOK 模型列表。
- 保存时仍写入现有编队成员 `model` 字段，不新增字段。
- 已有无法匹配到 adapter 的模型值继续显示并允许兼容保存，避免旧配置被静默清空。
- 没有 BYOK adapter 时保留当前手动输入能力，并显示适当的空状态或提示。

## 组件边界

优先复用现有组件和逻辑：

- `SettingsSidebarNav.tsx`：团队侧边栏入口和图标归类。
- `settingsSearch.ts`：团队搜索标题和路由索引。
- `ProviderSettingsPanel.tsx`：供应商列表过滤团队运行时实例。
- `MulticaRuntimeSettings.logic.ts`、`MulticaRuntimeSettings.model.ts`、`MulticaRuntimeSettings.validation.ts`：配置读取、草稿模型和保存校验。
- `CompositionSquadPanel.tsx`：编队成员编辑和现有 `model` 字段。
- `settings.squads.tsx`：团队页面组合现有编队能力和新增团队运行时区域。
- `messages.ts`：新增或调整中文源文案，并保持现有 i18n 目录规则。

若现有逻辑无法直接承载团队运行时编辑界面，只新增一个职责明确的团队运行时面板组件，不改动服务器运行时组件。

## 交互与异常处理

- 无连接环境：团队沿用现有环境空状态，不渲染可写表单。
- 无团队运行时实例：显示“尚未配置团队运行时”的空状态，并提供团队内的新增入口。
- 团队运行时配置解码失败：显示实例标识和不可用状态；保留原始配置，不自动覆盖或删除。
- 保存校验失败：显示对应字段错误，不提交部分配置。
- 保存成功：刷新当前设置和相关列表，避免继续显示旧实例或旧启用状态。
- Secret 环境变量：继续显示脱敏占位；未重新输入 Secret 时不得写入空值覆盖原 Secret。
- BYOK 模型列表加载失败：不阻塞团队编队页面，其余手动模型值仍可查看；明确显示模型来源不可用。

## 测试与验收

### 单元和组件测试

1. Provider 列表过滤：包含多个普通 Provider 和多个团队运行时实例时，结果不含任何团队运行时实例。
2. Provider 兜底分支过滤：团队运行时实例不会因未知驱动兜底逻辑重新出现。
3. 团队实例读取：能列出全部团队运行时实例，并正确保留启用状态、运行时身份和 Secret 原始身份。
4. 团队保存：合法草稿写回原有 `providerInstances`，非团队运行时配置保持不变。
5. 非法草稿：运行时身份、URL、Header、路由和 MCP 约束错误时拒绝保存。
6. BYOK 模型选择：可用 adapter 出现在 Agent 编队成员模型选择中，已有手动模型值不被清空。
7. 侧边栏和搜索：团队显示在设施区，点击和搜索都指向 `/settings/squads`。

### 浏览器验收

在当前本地开发服务中完成以下路径检查：

1. 打开 `/settings/providers`，确认页面不显示任何团队运行时实例。
2. 从侧边栏打开“团队”，确认团队运行时和 Agent 编队区块可见。
3. 查看至少一个团队运行时实例的编辑状态，确认字段和脱敏行为正常。
4. 在 Agent 编队成员中选择或填写 BYOK 模型，确认保存后仍可见。
5. 检查浏览器控制台没有由本次改动引入的错误。

### 验证边界

本次变更只覆盖前端归类和配置入口。真实团队运行时守护进程、真实 BYOK Provider API、跨客户端同步和发布包验证不属于本次验收范围，不能用本地页面可见性替代这些验证。

## 风险与回滚

### 风险

- 只调整界面归类，旧的外部链接若硬编码“供应商”语义可能需要同步修正。
- 编队成员模型目前是字符串字段，BYOK 选择器需要保留无法匹配模型的兼容显示。
- 当前工作区存在大量与本任务无关的脏改动，提交时必须只选择本设计或本任务文件。

### 回滚

- 代码回滚：恢复 Provider 过滤、侧边栏文案、团队页面组合和模型选择相关文件即可。
- 数据回滚：本方案不迁移、不删除 `providerInstances` 数据，因此回滚代码后原团队运行时配置仍可读取。
- 紧急回滚原则：不执行数据库删除、设置清理或凭据重写。

## 完成标准

- 供应商页面完全不显示团队运行时实例。
- 侧边栏有可达的“团队”入口。
- 团队可展示和编辑现有团队运行时实例。
- Agent 编队成员支持 BYOK 模型，且不破坏已有手动模型值。
- 对应前端测试通过，浏览器关键路径可达，工作区无无关文件被提交。
