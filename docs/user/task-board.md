# 任务看板

在「用量 → 任务与运行 → 任务图」中，可以配置子任务的串行或并行执行方式。并行模式可设置 1 到 64 个子任务的最大并发数；串行模式固定为 1。填写主任务后可先「保存到待办」，以后从看板重新载入、修改或删除；即使当前没有可用的任务图驱动，也可以先保存主任务。启动成功后，该待办会从本地列表移除。待办只保存在当前设备和浏览器中，不会同步到其他设备。开始后，看板按「待执行、执行中、待处理、已结束」显示任务状态，点击运行任务卡片可查看事件和可用操作。

「待处理」包括需要输入、审批或复核的任务，也包括失败后可重试的任务。可以按当前状态取消、继续、审核或重试；实际可用按钮以所选任务为准。看板状态来自服务端任务记录，刷新页面后仍可重新读取。

并行执行时，需要为每个子任务填写不同的工作目录，通常是预先创建的独立 worktree；留空会沿用主任务目录。如果多个并行子任务最终指向同一目录，界面会拒绝启动。串行执行可以共用目录。Code Work 不会在此表单中自动创建或合并 worktree。

选中任务后，「工作目录 Git 状态」会读取该任务实际保存的执行目录，并显示当前分支、改动文件和相对默认分支的领先提交数。「查看差异」按需读取工作区和分支差异，过长时会标出截断。旧任务或执行输入无法读取时，目录状态可能缺失；目录不是 Git 仓库时会明确提示。这里是只读快照，刷新按钮可重新读取。任务审核仅决定任务运行流程，不会自动合并 Git 变更。接收代码前仍须检查完整差异、目标分支和合并结果；任务显示「已完成」不表示代码已合入目标分支。
