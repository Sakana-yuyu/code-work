# 刷新模型目录

多个客户端在同一供应商配置下同时刷新状态和模型列表时，会共用正在进行的一次检查。检查结束后再次刷新会重新检查。配置发生变化时，旧设置的检查结果不会覆盖当前状态。

新增或编辑自定义模型服务时，模型发现会依次尝试服务支持的目录地址。一次发现共用 15 秒请求预算，连接、跳转和读取模型列表都包含在内；候选地址较多不会逐个延长等待时间。

查询成功后显示服务返回的模型。查询超时或失败时会显示原因；如果当前配置已有成功获取的目录，可以继续显示旧模型并标记为过期，待服务恢复后再次刷新。修改密钥或自定义请求头后，不会沿用旧凭据对应的缓存。

目录地址发生跨源跳转时，Code Work 不会向下一来源转发 Authorization、API Key、Cookie 等已识别的认证请求头。需要使用另一服务的模型时，应直接配置该服务地址及对应凭据。

这些行为适用于 Web、桌面端和手机端连接的服务器。本地连接、远程连接与隧道连接使用相同的服务端目录查询规则。
