# 刷新模型目录

多个客户端在同一供应商实例下同时手动刷新状态和模型列表时，会共用正在进行的一次检查。检查结束后再次手动刷新会重新检查。配置发生变化时，旧设置的检查结果不会覆盖当前状态。

自定义模型服务的状态检查、已保存配置和草稿模型发现共用模型目录。地址、协议、凭据、自定义请求头与目录设置相同的配置，可以在一分钟内复用成功结果；实例名称和模型通道名称不影响共享。手动刷新会跳过这份缓存。如果后台检查已经读到了旧缓存，手动刷新会接着执行一次新查询；同时发起的手动刷新仍会合并。草稿发现不会保存配置或创建对话。

Cursor 和 Grok 的模型目录也会在配置等价的实例之间共享一分钟成功结果。手动刷新会重新查询，失败后可以再次尝试。命中目录缓存时，Cursor 仍会检查版本和登录状态，Grok 仍会检查版本和技能列表；各实例配置的自定义模型也会分别保留。Grok 不会把目录查询成功当成已登录。更换其配置目录或修改模型路由后，会查询对应的新目录。仅修改实例名称不会重复启动模型探针。

Kimi、Antigravity、通用 ACP Agent，以及 Pi、OhMyPi、ZCode 的配置模型目录同样可以跨实例共享。前三者按有效的自定义模型列表共享，模型名两端空格、空项和重复项不影响共享；后三者按当前路由的模型标识、显示名称和实际模型名共享。修改模型列表或路由后会使用对应的新目录，手动刷新会重新生成。版本、安装与登录状态继续实时检查；ZCode 官方登录凭据也不会随目录缓存。配置模型目录本身不创建对话。Kimi 开启 BYOK 路由后，最终可选模型仍以当前网关配置为准。

Codex 和 Claude 也会在配置等价的实例间共享模型、技能或命令目录，登录状态仍随每次检查更新。Codex 的 ChatGPT 账户有邮箱信息时，可以复用一分钟目录；使用 API Key、Amazon Bedrock 或未返回可区分账户信息时，每次检查重新查询，同时发起的查询仍会合并。修改自定义模型后，各实例分别显示自己的模型。退出登录且需要认证时，不显示之前登录账户的原生模型。若切换组织后模型没有及时变化，可以手动刷新。

Claude 每次检查都会重新读取当前账户与原生命令；相同配置下的一分钟缓存复用模型与本地技能目录。变更命令、版本、配置目录或自定义模型后，会生成相应目录。初始化失败时显示无法验证认证状态，不把失败结果写成成功缓存。两者发现目录都不会向供应商发送用户消息或保存空白对话，手动刷新会重新加载目录。

OpenCode 会合并配置等价实例正在进行的目录检查，模型、模式和技能来自同一次查询。检查完成后再次刷新，会重新读取当前连接状态；断开供应商或重新连接后，可选模型随下一次检查更新，各实例的自定义模型分别保留。一次查询共用十五秒工作预算，包含本地版本检查与重试，多个请求不会逐个延长预算。超时后显示错误并释放请求；本地命令退出清理可能额外花费短暂时间。目录检查不会新建对话或启动本地 OpenCode 服务。

新增或编辑自定义模型服务时，模型发现会依次尝试服务支持的目录地址。一次发现共用 15 秒请求预算，连接、跳转和读取模型列表都包含在内；候选地址较多不会逐个延长等待时间。同一实例的状态检查也共用十五秒预算，多个模型通道不会逐个延长等待；超时后保留已完成的结果或同配置之前成功获取的模型。

查询成功后显示服务返回的模型。查询超时或失败时会显示原因；如果当前配置已有成功获取的目录，可以继续显示旧模型并标记为过期，待服务恢复后再次刷新。修改密钥或自定义请求头后，不会沿用旧凭据对应的缓存。

目录地址发生跨源跳转时，Code Work 不会向下一来源转发 Authorization、API Key、Cookie 等已识别的认证请求头。需要使用另一服务的模型时，应直接配置该服务地址及对应凭据。

这些行为适用于 Web、桌面端和手机端连接的服务器。本地连接、远程连接与隧道连接使用相同的服务端目录查询规则。
