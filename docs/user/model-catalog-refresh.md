# 刷新模型目录

多个客户端在同一供应商实例下同时手动刷新状态和模型列表时，会共用正在进行的一次检查。检查结束后再次手动刷新会重新检查。配置发生变化时，旧设置的检查结果不会覆盖当前状态。

自定义模型服务的状态检查、已保存配置和草稿模型发现共用模型目录。地址、协议、凭据、自定义请求头与目录设置相同的配置，可以在一分钟内复用成功结果；实例名称和模型通道名称不影响共享。手动刷新会跳过这份缓存。如果后台检查已经读到了旧缓存，手动刷新会接着执行一次新查询；同时发起的手动刷新仍会合并。草稿发现不会保存配置或创建对话。

Cursor 在配置、已检测版本、更新渠道和账户身份相同的实例之间，可以共享一分钟成功模型目录；版本、账户或套餐变化后会重新查询。登录状态未知、没有稳定账户标识或无法识别版本时，也会重新发现模型。每次仍检查当前版本和登录状态；多个客户端的等价检查共用十五秒工作预算，后加入者不会重新计时。超时保留已确认的版本和登录信息，并显示提示。各实例的自定义模型分别保留，手动刷新会重新查询。

Grok 的模型目录也会在配置等价的实例之间共享一分钟成功结果，命中缓存时仍检查版本和技能列表，不会把目录查询成功当成已登录。更换其配置目录或修改模型路由后，会查询对应的新目录。各实例的自定义模型分别保留，手动刷新会重新查询，失败后可以再次尝试。仅修改实例名称不会重复启动模型探针。

Kimi、Antigravity、通用 ACP Agent，以及 Pi、OhMyPi、ZCode 的配置模型目录同样可以跨实例共享。前三者按有效的自定义模型列表共享，模型名两端空格、空项和重复项不影响共享；后三者按当前路由的模型标识、显示名称和实际模型名共享。修改模型列表或路由后会使用对应的新目录，手动刷新会重新生成。版本、安装与登录状态继续实时检查；ZCode 官方登录凭据也不会随目录缓存。配置模型目录本身不创建对话。Kimi 开启 BYOK 路由后，最终可选模型仍以当前网关配置为准。

Codex 和 Claude 会在配置等价的实例间共享正在进行的完整检查，后续检查重新读取登录状态。Codex 的 ChatGPT 账户有邮箱信息时，可以复用一分钟目录；使用 API Key、Amazon Bedrock 或未返回可区分账户信息时，每次检查重新查询。修改自定义模型后，各实例分别显示自己的模型。Codex 退出登录且需要认证时，不显示之前登录账户的原生模型。若切换组织后模型没有及时变化，可以手动刷新。

Claude 每次检查都会重新读取当前账户与原生命令；相同配置下的一分钟缓存复用模型与本地技能目录。变更命令、版本、配置目录或自定义模型后，会生成相应目录。初始化失败时显示无法验证认证状态，不把失败结果写成成功缓存。两者发现目录都不会向供应商发送用户消息或保存空白对话，手动刷新会重新加载目录。

Codex 的版本、账户、模型、技能及必要诊断共用十秒工作预算；Claude 的版本、初始化和技能扫描共用三十秒，较慢的初始化不会让每个阶段重新计时。超时或取消会释放本次查询资源，释放过程可能额外花费短暂时间。Claude 在版本已确认后超时，会保留已确认的安装和版本信息。手动刷新可重新查询目录，先前普通检查的旧结果不会覆盖这份新目录缓存。

OpenCode 会合并配置等价实例正在进行的目录检查，模型、模式和技能来自同一次查询。检查完成后再次刷新，会重新读取当前连接状态；断开供应商或重新连接后，可选模型随下一次检查更新，各实例的自定义模型分别保留。一次查询共用十五秒工作预算，包含本地版本检查与重试，多个请求不会逐个延长预算。超时后显示错误并释放请求；本地命令退出清理可能额外花费短暂时间。目录检查不会新建对话或启动本地 OpenCode 服务。

新增或编辑自定义模型服务时，模型发现会依次尝试服务支持的目录地址。一次发现共用 15 秒请求预算，连接、跳转和读取模型列表都包含在内；候选地址较多不会逐个延长等待时间。同一实例的状态检查也共用十五秒预算，多个模型通道不会逐个延长等待；超时后保留已完成的结果或同配置之前成功获取的模型。

同一次目录发现会统一释放发出的请求，包括尚未读完的跳转响应。一个地址失败后仍可继续尝试下一个地址；整次查询成功、失败或超时后才结束这次加载。多个等待者共用查询时，一个等待者先超时不会取消其他等待者仍需要的结果；新的刷新使用新的请求生命周期。

查询成功后显示服务返回的模型。查询超时或失败时会显示原因；如果当前配置已有成功获取的目录，可以继续显示旧模型并标记为过期，待服务恢复后再次刷新。修改密钥或自定义请求头后，不会沿用旧凭据对应的缓存。

目录地址发生跨源跳转时，Code Work 不会向下一来源转发 Authorization、API Key、Cookie 等已识别的认证请求头。需要使用另一服务的模型时，应直接配置该服务地址及对应凭据。

Kimi 的一次目录刷新也共用十五秒工作预算，包括代理模型路由、配置模型目录和版本检查。等价配置共享正在进行的检查，晚加入不会延长预算；版本命令挂起时显示超时原因，恢复后可再次刷新。停用 Kimi 时仍检查实际安装状态，便于区分已安装和需要安装。目录刷新不建立对话，也不替代官方登录验证。

Antigravity 的配置模型和版本检查同样共用十五秒工作预算。等价配置的并发刷新共用检查，晚加入不会延长等待；命令挂起时显示原因，恢复后可以再次刷新。停用实例仍检查实际安装状态，官方认证由真正的对话运行确认，目录检查不建立对话。进程退出与文件系统清理可能额外耗时。

通用 ACP Agent 的配置模型和命令检查共用八秒工作预算。命令、参数、环境与模型配置等价的实例共享正在进行的检查，晚加入不会延长预算；命令挂起时显示原因，恢复后可再次刷新。命令不支持版本参数时仍允许进入真正的对话握手，登录和模型支持由实际会话确认，目录检查不建立对话。

Pi、OhMyPi、ZCode 的路由模型、版本以及 ZCode 官方登录信息共用十五秒刷新工作预算。等价配置共享正在进行的检查，晚加入不会延长等待。路由读取失败时不提供模型，但仍如实检查 CLI；官方登录信息读取超时时保留已确认的安装和版本，显示认证未知与超时原因。停用实例与 ZCode 内嵌运行时仍跳过版本命令，下一轮刷新重新读取当前账户。目录刷新不建立对话，进程和文件系统清理可能额外耗时。

Grok 的一次目录刷新共用十五秒工作预算，包括代理路由准备、版本、技能和模型查询。多个相同配置的请求共用正在进行的检查，晚加入不会延长预算。超时后保留已经读取的版本和技能，并显示原因；服务恢复后可再次刷新。当前认证协议无法提供稳定账户身份，因此下一轮仍重新读取目录，避免切换账号后继续显示旧模型。目录检查不新建对话或发送消息。

Grok 代理实例默认使用独立目录，刷新时的模型列表与托管配置使用同一轮路由设置。个人默认账号目录保持只读。为不同实例配置目录时应使用各自独立目录；多个实例同时写入同一目录可能相互覆盖配置。进程退出和文件系统清理可能使实际返回时间超过工作预算。

这些行为适用于 Web、桌面端和手机端连接的服务器。本地连接、远程连接与隧道连接使用相同的服务端目录查询规则。
