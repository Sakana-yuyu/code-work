# 回复输出方式

在 Web 或桌面应用的「设置 → 通用 → 回复输出方式」，或手机应用的服务器设置中，选择当前环境的回复输出方式。此设置由服务器保存；连接同一环境的设备使用同一个选择。

- **按段落（默认）**：段落、代码块和列表项完整后逐步显示。小标题与下方正文一起出现，代码围栏闭合前保留整个代码块。
- **完整回复**：在当前消息结束、工具开始或需要审批/补充信息时显示已经收到的正文。
- **逐 token（遗留模式）**：立即显示收到的文本增量，适合仍需要原有输出方式的用户。

新环境默认按段落显示。已有环境如果明确配置过旧版逐 token 开关，会保留原有选择：开启对应逐 token，关闭对应完整回复。可以随时改成按段落；Web 与桌面的恢复默认设置会恢复按段落。

在回复过程中修改模式时，已经收到的文本会保留。回合正常结束、失败或取消时，剩余文本也会显示。等待审批和补充信息时会刷新当前文本，便于依据 agent 的说明作出决定。

服务器会合并短时间内密集到达的文本：空闲后的首个增量立即处理，后续增量以约 60ms 的窗口合并。工具、审批和回复结束仍按收到的先后顺序处理；结束时完整尾文与完成状态一起显示。正文与思考内容分别合并，图片、音频和文件保留独立内容。逐 token 模式也使用该合并节奏。

Web、桌面与手机中的线程及环境状态按屏幕刷新帧更新。同一帧内的多次变化会一次显示完整的最新状态；重新打开线程时也会恢复离开前已收到的内容和完成状态。

支持平滑文字显示的环境会在同一设置区显示 **平滑显示文字**，默认开启。新增文字按积压量逐步显示，积压较大时加快追赶；第一次打开回复时显示已经收到的全文，回复结束时显示全部尾文。关闭开关会立即追上当前全文，恢复默认设置会重新开启。服务器保存此选择，连接同一环境的设备共享设置。

显示节奏不会截断消息、历史或代码复制，也不会把 emoji 和组合文字拆开。积压期间，滚动尺寸仍按已经收到的全文计算。开始选择或复制代码时会追上全文；Web 与桌面中已有选区会保持原来的文字，后续尾文在清除选区后显示，回复结束也保留正在选择的文字。

旧环境未声明平滑文字能力时不显示这个开关，继续使用原有显示方式。

如果设置提示服务端不支持输出模式，需要先更新对应环境的服务器。连接旧服务器时，三态控制禁用。

Web 与桌面中的回复会保留已经显示的段落和代码行。使用逐 token 模式时，选中已经显示的代码后，后续代码行的追加和回复结束会保留该选区；复制代码仍包含当前已收到的完整代码。

流式回复期间，已完成回合的回退操作仍对应原回合；新的检查点会及时更新可回退位置。

离开线程页面后，环境连接与 agent 的工作继续保留。短时间内重新打开同一线程，会先恢复已显示的内容和历史分页位置，再接收离开期间的新事件；已显示的内容与进度一起缓存 5 分钟。

手机中的 Markdown 块也会在尾部追加时保持身份。流式回复会复用已完成的段落和代码块，继续显示新收到的正文；正文替换或后来的引用定义仍会更新前面的内容。iOS 与 Android 代码高亮计算期间都会继续显示已经着色的行，并以普通文字显示新收到的尾部，随后更新高亮。更换语言、主题或关闭高亮后，代码会使用相应的新样式。

手机收到新的正文时，会保留已显示的历史消息、工具行和折叠状态。工具更新、消息顺序变化、回复结束或展开历史时，列表继续更新相应内容。

新的工具活动会追加到当前列表，已经展开的其他工具行继续保留。工具与子 agent 的后续状态会更新对应行，较晚到达的事件和重新加载的历史仍按正确顺序显示。
