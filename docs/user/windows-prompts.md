# Windows 上发送较长输入

在 Windows 环境使用 Antigravity 或 ZCode 时，输入正文会作为启动参数发送给供应商。Windows 对完整命令行有长度限制；`.cmd` / `.bat` 启动入口的限制更小。输入中的引号、空格以及续接参数也会占用长度，因此可发送的正文长度不是固定字符数。

超过限制时，Code Work 会在启动该次请求前显示 `AGENT_PROMPT_TOO_LARGE`，说明超限阶段并给出处理建议。正文不会被自动截断，也不会自动重试。

可以缩短输入，把较长内容保存为供应商能够读取的项目文件，并在消息里引用该文件；也可以选用通过标准输入、RPC 或 HTTP 发送正文的供应商，例如 Codex、Claude 或自定义模型服务。更换供应商时请确认目标环境中的登录与模型配置。

若当前入口是 `.cmd` / `.bat`，可以在供应商设置中选择该 CLI 提供的直接可执行文件；ZCode 也可以使用内置运行时。直接入口仍有命令行长度限制，不能保证任意长度都能发送。

`.cmd` / `.bat` 无法完整传递的多行输入会提示 `AGENT_PROMPT_UNSUPPORTED`，此时改用直接可执行文件或内置运行时。应用不会为了让命令启动而删除换行。

这个检查由运行供应商的环境执行。Web、桌面和手机连接同一个 Windows 环境时采用相同限制；从 Windows 客户端连接其他操作系统的环境时，以目标环境为准。Antigravity 自动生成线程标题、分支名、提交信息和 PR 内容也使用同一检查与提示。

输入修正后可以重新发送。错误提示不包含原始正文或密钥；失败不会更改供应商的权限模式。
