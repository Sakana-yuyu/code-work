# 使用 Pi / OhMyPi / ACP Agent 供应商

Code Work 支持三类新供应商：**Pi** 与 **OhMyPi** 是只能用你自己的模型线路运行的 CLI agent；**ACP Agent** 是一个通用入口，任何支持 Agent Client Protocol 的 CLI 都能接入。三者在 **设置 → 供应商** 中添加，默认关闭，需要自行安装对应 CLI。

## Pi 与 OhMyPi：完全运行在你的自定义模型服务上

Pi 和 OhMyPi 没有自己的登录或付费账号。Code Work 会为它们维护一份受管理的配置，里面**只**注册你的自定义模型服务作为模型来源，并且清空了其它模型服务的密钥环境变量——这两个 CLI 从构造上就无法使用别的凭据，也不会把你的渠道密钥带进它们自己的配置目录。

准备步骤：

1. 在 **设置 → 供应商** 添加一个 **自定义模型服务** 实例，并在其中配置模型通道。
2. 只有 **OpenAI 协议** 和 **Anthropic 协议** 的通道会被使用；Gemini 协议通道不在这两个供应商的可用范围内。
3. 安装对应的 CLI（`pi` 或 `omp`），然后在 **设置 → 供应商** 添加 Pi / OhMyPi 实例。

行为说明：

- 模型选择器里出现的模型就是你的模型通道；没有可用通道时，对话会直接报错提示先配置模型服务，不会悄悄借用其它凭据。
- 修改模型通道后，Pi / OhMyPi 会在当前运行的任务结束后自动使用新的通道配置。
- 图片附件（PNG / JPEG / WebP / GIF）会随消息一起发送。

### OhMyPi 的工具审批

OhMyPi 自带的 bash / 编辑 / 写入工具遵循对话的权限模式：

| 权限模式                 | OhMyPi 行为                            |
| ------------------------ | -------------------------------------- |
| Supervised               | 每个内置工具都先询问（Approve / Deny） |
| Auto-accept edits / Auto | 文件写入自动通过，命令等仍会询问       |
| Full access              | 全部自动通过                           |

审批会以对话内请求的形式出现，批准或拒绝后 agent 继续。也可以在实例设置中把 **原生工具审批模式** 固定为 询问 / 写入 / 全自动，覆盖随权限模式变化的默认行为。

### 限制 Pi 的内置工具

Pi 的内置工具没有审批协议，只做展示。如需限制它可用的工具，在实例的 **启动参数** 里填 CLI 原生参数，例如 `--tools read,grep` 只保留读取和搜索。

## ACP Agent：接入任意 ACP CLI

Web 和桌面可在“添加供应商”中点击 **GitHub Copilot ACP**，选择目录中的版本并确认启动命令，随后保存。
已有安装也可手工填写 `copilot --acp`，认证方式建议填写 `copilot-login`；请先在对应服务器使用官方 CLI 完成登录。
通用 ACP 的“CLI 默认模型”表示不覆盖 CLI 自己的模型选择，不是具体模型名称。Mobile 可通过 ACP Agent 手工配置同样的命令。能连接不代表所有模型或自定义 Agent 都可选择：1.0.89 实测没有通过 ACP 提供模型列表，界面不会凭空生成该列表。

Web 和桌面也可点击 **Gemini ACP**，选择目录版本后保存；快捷入口预填 Google 登录方式 `oauth-personal`。
请先在所选服务器使用官方 Gemini CLI 完成登录。使用 API Key 时将认证方式改为 `gemini-api-key`，
并在该环境或实例的敏感变量中配置 `GEMINI_API_KEY`，不要写入命令行。Mobile 可在 ACP Agent 中手工配置同样的命令与认证方式。
通用默认认证名 `login` 不适用于 Gemini；认证请求成功仍可能在建立会话时报告缺少密钥，此时不会继续发送消息。
Gemini 原生协议不会因开启 OpenAI/Anthropic 网关开关就自动接入共享渠道，请使用该 CLI 实际支持的认证和端点设置。

Qwen Code 可从 ACP 目录搜索并选择，认证方式会预填 `openai`。在所选服务器环境或实例敏感变量中配置 `OPENAI_API_KEY`，并按模型服务设置 `OPENAI_BASE_URL` 与 `OPENAI_MODEL`；不要把密钥写入启动命令。目录固定版本 0.24.7 需要 Node.js 22 或更高版本。选择另一个目录条目会同步更新认证方式，仍可按实际安装手工修改。需要逐次批准工具时，请同时核对 Agent 模式与 Code Work 的权限设置，Qwen 自身的自动模式可能直接执行工具。

Cline 从 ACP 目录选择后，认证方式预填为空，使用目标服务器上 `cline auth` 已保存的登录或 `CLINE_API_KEY` 环境凭据。可按官方配置设置 `CLINE_PROVIDER` 与 `CLINE_MODEL`；空认证只省略交互式认证步骤，缺凭据仍无法建立会话。需要显式登录时可按账号填写 `cline`、`cline-pass` 或 `openai-codex`，通用 `login` 不适用。模型列表为空时先检查 Cline 的模型服务配置，不应把登录供应商名称当成模型。

Cline 使用 OpenAI 兼容服务时，`CLINE_PROVIDER` 应填写 `openai-compatible`。3.0.65 的 ACP 模式请用 `CLINE_DATA_DIR` 指定独立数据目录，不能仅依赖 `--data-dir`。批量命令的输出可在工具详情展开查看；其中一条明确失败时整组标记失败。审批按 Agent 提供的选项回传，不同 Agent 的选项名称可以不同。

Windows 可以填写已安装的 `.cmd` / `.bat` 入口，或通过环境 PATH 查找的命令。
路径或参数含空格时请加双引号，例如 `"C:\My Agents\agent.cmd" --workspace "D:\My Project"`。
健康检查和会话启动使用同一入口；命令可启动不表示登录已经完成。

在线目录暂时不可用时，仍可搜索程序内置的目录快照，页面会显示快照日期和版本
可能过期的提示。选择条目前请确认所需版本；手工命令入口始终保留。目录恢复后
重新获取时使用在线结果，离线目录本身不保证软件包能下载或账号已登录。

ACP Agent 面向支持 Agent Client Protocol（JSON-RPC over stdio）的 CLI。添加实例时可以先搜索 ACP Registry，选择带固定版本 npx 或 uvx 命令的 Agent；命令会填入配置表单，保存实例后可继续编辑。Code Work 探测或启动该命令时，npx/uvx 可能在所选环境下载软件包。若目录提供带校验的官方二进制，可在所选环境上一键下载并安装，校验通过后自动填入启动命令。目录不可用、Agent 需要其他安装方式，或用户已有安装时，也可以手工填写命令。

手机端在“供应商”设置的“添加供应商实例”中选择 ACP Agent 后，同样可以搜索目录并点“使用”。所选条目的命令、认证方式、环境参数和 MCP 默认设置会随实例保存，实例 ID 为空时会自动建议一个；添加后在实例卡片中修改命令或其它设置。列表一次只显示部分匹配项，可输入名称缩小范围。

主要配置项：

- **命令行**：完整的启动命令，例如 `npx -y cline@3.0.46 --acp`。
- **认证方式**：会话建立时使用的认证方法名，默认 `login`，按目标 agent 的文档填写。主动清空后会保存为空，直接使用 CLI 已有登录或环境凭据建立会话，由 CLI 校验是否可用；Web、桌面和 Mobile 保持一致。
- **注入 Code Work MCP 工具**：默认开启。若 Agent 在建立会话时拒绝 MCP 服务器，可关闭；关闭后 Code Work MCP 工具不可用，Agent 自带工具和标准文件、终端能力仍按原规则运行。修改在新建或恢复会话时生效。Factory Droid 目录按兼容设置默认关闭，使用支持 MCP 的版本时可以重新开启；已保存实例不会被自动改动。Web、桌面和 Mobile 均可修改此项。
- **通过共享模型网关路由**（可选）：开启后向 agent 注入标准的 OpenAI / Anthropic 端点环境变量，指向你的自定义模型服务网关。注意这是"优先注入"而不是强制——只有读取这些环境变量的 agent 才会走你的共享线路，自带登录的 agent 仍用它自己的账号。

ACP Agent 的模型、登录和工具行为由它自己解释；文件与终端请求仍受 Code Work 的工作区约束和审批链管理。目录在所选环境的服务端读取；仅能安全转换为固定版本 npx 或 uvx 命令的条目可直接选择。其他条目会提示需要手工配置或当前环境平台不支持。命令可用性由实例的现有探测状态显示，实际 ACP 认证仍需在会话建立时确认。

会话建立后，如果 Agent 提供命令列表，在输入框输入 `/` 即可查看。选择命令会填入输入框，可继续补充参数，然后自行发送；命令由当前 Agent 处理。列表会随会话更新，Agent 撤回的命令也会从菜单移除。新草稿尚未连接 Agent 时，可能还没有会话命令；不同供应商实例的命令互不混用。Web、桌面和 Mobile 沿用各自的输入菜单。

Agent 提供模型目录时，当前线程的模型菜单会随会话更新，可选择新出现的模型用于下一条消息。
上游撤回的模型不再作为会话选项显示，手工配置的自定义模型仍保留。新草稿使用实例原始配置；
新会话未提供模型目录时也恢复到原始配置。目录只影响当前线程和对应实例，不会改写其它账号。
能看到模型名称不表示登录或该模型的实际调用已经成功。

Agent 提供会话模式时，可在模型参数菜单（Mobile 为会话设置）中选择“Agent 模式”，下一条消息使用所选模式。
模式名称和说明来自 Agent，可能影响可用工具和权限；请按说明选择。列表随当前会话更新，不同实例互不混用。
已撤回或格式无效的选择会被拒绝，不会自动改用另一模式继续执行。Web 和桌面此时使用完整模式选项，隐藏旧计划开关。
未连接的新草稿或未提供模式的 Agent 没有该选项；其它配置项尚未全部开放为通用控件。

Copilot 广告自定义 Agent 后，可在同一模型参数菜单选择 **Agent**，选择 **Copilot** 可恢复默认角色。
**Allow All** 控制 Copilot 是否直接执行工具；保持 **Off** 且将 Code Work 权限设为 **受监督**，才能按请求人工审批。
选择 **On** 会让 Copilot 自动允许工具、路径和网络操作，不能把它当作普通显示选项；它与 Autopilot 是不同配置。
这些选择在下一条消息提交时应用。窄屏在“更多输入控件”中选择，Mobile 使用会话设置；撤回的候选不可继续提交。
目前开放上游的角色与权限 select 配置，其它未知配置控件不会凭空补出。

Agent 返回资源链接或嵌入文本资源时，聊天中会保留链接目标、说明和资源原文。
HTTP(S) 与文件链接沿用现有打开方式；其它 URI 会显示“不支持直接打开”，可复制后在对应工具中使用。
嵌入文本按原文显示，其中的 HTML、图片和链接语法不会自动执行。回合结束后，中间资源消息可能收在“工作了…”记录中，展开即可查看。
Agent 返回的 PNG、JPEG、GIF 和 WebP 图片会保存到当前环境，在聊天中显示并可点击预览，刷新后仍可查看。
每张图片最多 10 MiB；格式、编码无效或保存失败会显示具体错误，无法解码的图片显示“图片不可用”。
图片中间回复可能收在工作记录中，展开即可查看；只有图片的最终回复仍正常显示。思考流里的图片不公开显示。
不支持的格式不会自动转换，也不会自动下载上游提供的图片网址。
## 助手音频与文件

Agent 返回的常见音频（如 WAV、MP3、OGG、WebM、AAC、FLAC）会保存到当前环境，网页端可直接播放，移动端可通过附件入口打开；嵌入的二进制资源可下载，可执行或可脚本化类型会被拒绝。音频与二进制同样最多 10 MiB，且只接受内联数据，不会按上游网址回源下载。思考流里的音频和二进制资源不公开显示。

音频播放失败会显示不可用；移动端打开附件失败会提示并保留点击重试入口。

## 窄屏聊天顶栏

Web 和桌面的聊天区域较窄时，顶栏会将项目、线程标题与操作按钮分行显示。
标题仍可打开线程操作；工作区、项目操作、编辑器和 Git 入口保留在下一行，空间不足时继续换行。
打开右侧面板后也按聊天区域的实际宽度调整；较长的标题会省略显示，可通过标题提示查看完整名称。


目录会标出与该条固定版本命令及必要环境参数匹配的实例状态，包括检查中、可用、命令缺失、启动失败和已停用。只有软件包版本与目录 Agent 版本一致时才会预填命令；版本不一致的条目仍可手工配置。未配置只表示没有匹配的实例，不代表软件包未安装。命令探测返回非零退出码时会显示简要原因，不会回显可能包含敏感内容的原始输出；如果 Agent 明确不支持 `--version`，会显示命令已启动，并在实际 ACP 会话中确认握手和认证。

选择 Auggie、Factory Droid 或 fast-agent 时，向导会显示并随实例保存目录中的公开环境默认值。切换到其它目录条目会替换这些参数；手工修改命令会清除目录参数，避免沿用上一个智能体的设置。添加后可在实例设置的环境变量中编辑；账号凭据请使用敏感变量字段。

使用 npx 前请在所选服务器环境安装 [Node.js](https://nodejs.org/en/download)，使用 uvx 前请安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)。目录不会代为安装这些运行器。未知或尚未核对的目录环境参数会使条目保留为手工配置。

目录也提供 CodeWhale、Gajae Code、Hermes、Kiro CLI 和 TRAE CLI 的手工安装入口。请打开条目的“安装说明”，先在所选服务器上安装并完成登录，再使用预填命令。这里使用已安装的本机版本，不自动锁定或安装。Hermes 还需要 ACP extra；Gajae Code 会保留工具权限询问。平台不支持时不提供预填按钮，官方说明链接仍可查看。文档核对日期不代表账号或工具已经实测通过。

Hermes 请先运行 `hermes model` 配置模型，然后使用 `hermes acp`。认证方法保持为空，以使用 Hermes 已保存的配置；不要填写通用的 `login`。如需独立账号目录，在实例环境变量中设置 `HERMES_HOME`。可通过 `hermes acp --check` 检查 ACP 依赖，这项检查不代表模型账号或工具已经可用。

Kiro CLI 的官方 Windows 包目前仅提供 x64，要求 Windows 11；Windows ARM64 的目录条目会显示平台不可用。请在运行 Agent 的服务器上核对系统要求，并先完成官方安装和登录。`kiro-cli --version` 能运行只代表程序可启动，仍需建立会话确认 ACP 与账号可用；遇到主目录初始化错误时，请保留错误信息并检查官方支持的安装环境。

Gajae Code 使用 `gjc acp`，认证方法填 `agent`。新添加时目录会预填；已有实例若保存的是 `login`，请修改后重新连接。先在同一服务器上完成 Gajae 的模型和凭据配置：认证响应成功仍可能在发送消息时提示未选择模型。保留工具权限询问。当前已验证 v0.18.1 的握手、认证及失败后的正常会话关闭；该版本虽然列出 plan 模式，实际会拒绝切换。模型和工具完整流程仍在验证。

Windows 上的 Gajae 命令工具需要可用的 Bash。若工具提示找不到 Bash，请在 Gajae 的 `settings.json` 中将 `shellPath` 指向实际安装路径，例如 `C:/Program Files/Git/bin/bash.exe`，再执行一次无副作用命令确认。工具详情优先显示实际输出，输入命令仍单独保留。v0.18.1 的工作目录内写入可能直接执行，权限询问设置不能保证每次写入都需要批准。

停止 ACP 会话时，应用会先使用 Agent 提供的关闭能力。若关闭请求失败或超过 5 秒没有确认，会显示异常退出并释放本地连接；远端工作是否结束仍需确认。停止会话不会删除聊天历史。

Windows 上的 Hermes 文件和命令工具还需要 Git for Windows 的 Git Bash。如提示找不到 Git Bash，在实例环境变量中设置 `HERMES_GIT_BASH_PATH` 为实际 `bash.exe` 路径，例如 `C:/Program Files/Git/bin/bash.exe`。请通过一次文件读取和无副作用命令确认工具可用；只看到模型回复不能证明工具环境完整。

## Kiro 会话命令

连接 Kiro 后，其当前会话广告的命令会进入命令菜单。选择命令填写输入框，发送后执行；内置命令显示执行结果，拒绝或执行错误会显示失败，不自动重试。内置命令请单独发送，不能同时携带附件。取消或等待超过 60 秒只结束本次等待，操作状态可能未知，请先确认远端结果再重复操作。真实 CLI 的安装、认证和工具仍需在目标环境验证。


## Gajae 回合结束

Gajae 的回复结束后，会等待当前会话的空闲通知再执行下一条消息，避免连续回合冲突。等待期间仍可取消；超过 60 秒未确认空闲会显示远端状态未知，请先确认结果再重复操作。配置认证方式时按已安装版本填写；0.18.1 使用 agent。安装探测和认证方式被接受，不代表模型或账号余额可用。



ACP 工具返回结果后，后续的标题、类型或输入更新会保留已有结果正文和失败状态；输入命令与结果分别查看。Agent 明确返回新结果时更新正文，不会删除实际重复输出。长文本仍保留带截断提示的末尾内容。


ACP 工具结束后，本回合补充的标题或结果会更新原有记录，并保留已收到的结束状态和正文。下一条消息开始后，新工具记录不会继承上回合已结束工具的结果。补充通知不会触发工具再次执行。

## Gemini CLI 0.61.0 的恢复限制

Gemini CLI 0.61.0 的 ACP 恢复可能使已有会话失去可恢复的历史。恢复该版本时，应用会在发出恢复请求前显示明确错误并保留原历史；正常新建会话和工具调用仍可使用。请使用已经验证支持恢复的版本后再恢复，不要反复尝试同一故障版本。

该版本的命令失败有时只提供文字结果。应用会识别明确的非零退出标记并显示失败；若输出不含退出信息，应查看工具详情，不能仅凭上游完成标签判断命令成功。

## Copilot 自定义模型与命令状态

Copilot CLI 1.0.89 支持自定义模型端点。使用该路径时，认证方法留空；模型请求使用 CLI 中配置的模型，未广告目录时选择“CLI 默认模型”。需要人工确认工具时保持 Allow All Off；更改角色、模式和权限不会撤销此前已经执行的工具。

该版本的命令结果可能同时返回“已完成”和非零退出码。应用按明确的结构化退出码显示失败并保留原结果；没有退出码时不凭文字猜测。离线模式只向配置的模型端点请求，若希望本机运行，端点也必须是本机地址。

## Factory Droid 认证与 MCP

公共版 Factory Droid 0.229.0 需要有效 Factory 认证才能建立模型会话。检测到版本或完成握手不等于工具已可用；自定义模型配置也不能据此视为免登录。

目录默认关闭 Code Work MCP 注入，这是兼容设置。需要 MCP 时可以显式开启，并在认证后核对实际工具；关闭设置不影响标准文件、终端和审批接口。Factory 的企业离线版是单独分发的产品，公共安装包不能通过普通配置变成企业离线版。
