# 自定义模型服务与委派

自定义模型服务（BYOK，bring your own key）让你把自己的模型 API 端点接入 Code Work，用于普通模型对话、委派任务，也可以作为多个 CLI 共用的模型线路。

## 使用顺序

1. 在 **设置 → 供应商** 中添加供应商实例时选择 **自定义模型服务**。
2. 在 **设置 → 自定义模型服务** 中添加模型通道。每个通道可以使用不同的厂商、Base URL、API 密钥、协议和模型 ID。
3. 在 **设置 → 运行时** 中确认模型服务显示为“可用”。这里仅说明驱动是否就绪，不会创建任务或修改模型配置。
4. 在 **设置 → 委派** 中选择已就绪的模型服务实例，填写任务后创建委派。

## 让多个 CLI 共用一条模型线路

先在 BYOK 中配置一次服务地址、密钥和模型，再到 **设置 → 供应商** 打开目标 CLI 的连接设置，选择 **共享模型渠道**，从 **共享账号与模型线路** 中选择对应的 BYOK 实例并保存。Codex、Claude、Grok 和由当前服务器启动的 OpenCode 都有这个入口；手机端在 **设置 → Provider** 开启 BYOK 路由后选择共享线路。

选择具体线路后，模型列表和请求都限定在这条线路内。如果线路被删除，需要重新选择；系统不会自动借用其他线路。**全部 BYOK 线路（兼容旧设置）** 会保留旧配置聚合模型的行为。多个 CLI 可以选择同一个 BYOK 实例，修改该实例中的连接信息即可供它们共用。

每个 CLI 对上游协议的要求不同：

| CLI      | 共享线路必须提供的接口  |
| -------- | ----------------------- |
| Codex    | OpenAI Responses        |
| Claude   | Anthropic Messages      |
| Grok     | OpenAI Chat Completions |
| OpenCode | OpenAI Chat Completions |

Code Work 网关按原协议转发。标为 OpenAI 的通道不一定同时支持 Responses 和 Chat Completions；例如只提供 Chat Completions 的服务不能直接供 Codex 使用。先确认服务支持对应接口，再选择模型。

CLI 正在运行当前轮次时，修改它的连接模式或所选线路可以保存，但会显示“配置已保存，等待当前轮次结束后生效”。等待切换期间，该实例的新启动或新一轮请求会提示稍后重试。直接编辑共享线路中的地址、密钥或模型，则会影响网关收到的后续请求；需要保持任务线路稳定时，应在任务结束后编辑。需要恢复原生账号时，切回 **原生账号** 并保存；手机端关闭 BYOK 路由。Grok 的共享线路使用独立账号目录，避免改写个人默认 Grok 目录。

Cursor 的自定义端点需要兼容 Cursor 协议的专用桥，不能直接填写普通 CPA、Sub2API 或 OpenAI 地址；真实 Cursor ACP 桥接仍未完成验证。OpenCode 如果配置了外部服务地址，模型线路必须在外部服务所在环境配置，当前服务器不能接管该外部进程。

Web 和桌面端的 Grok 原生账号卡也提供登录与设备码登录按钮；新增 Grok 实例使用独立账号目录，可在不同实例间选择账号。

## 本地官方账号池（不依赖 CPA/Sub2API）

在同一页面的 **本地官方账号池** 中，可以直接选择官方 `auth.json` 文件，或者粘贴 Codex、Claude、Grok、Cursor 的凭据 JSON 导入当前 Code Work 服务器。凭据只写入服务端密钥存储，页面只显示账号名称、平台和启用状态。将账号池绑定到现有的 `codex`、`claudeAgent`、`grok` 或 `opencode` Provider 实例后，该实例会继续使用 Code Work 自己的本地网关，网关按启用账号轮询并把请求送到对应官方端点；当前对话的 CLI 不需要再切换配置。Cursor 使用 ACP 子进程，按会话启动时选择账号并注入 `CURSOR_API_KEY` 或 `CURSOR_AUTH_TOKEN`；ACP 进程启动后暂不支持依据 HTTP 状态自动重启换号。OpenCode 绑定时请选择 Codex 或 Grok 作为 OpenAI 兼容来源。

导入时可以选择官方 CLI 的 `auth.json`、粘贴凭据 JSON，或直接粘贴 API Key。凭据 JSON 可以提供 `models` 数组（或单个 `model`）来限制账号可服务的模型；没有模型声明的官方 OAuth 文件也允许导入，表示由对应 CLI/请求模型决定能力。只有声明了模型的账号才会出现在“连接为共享线路”生成的 BYOK 模型通道中，系统不会猜测或伪造模型名。OpenCode 的 Codex 本地线路只接受 API Key 账号；Codex OAuth 官方线路是 Responses 协议，不能直接作为 OpenCode 的 Chat Completions 后端。

账号池可以选择“轮询账号”或“优先用满当前账号”。绑定账号池后导入同平台账号会自动加入已有绑定；删除账号时，Code Work 会同时从已绑定的 CLI 实例中移除该账号。
账号列表支持勾选后批量启用或禁用，批量操作只修改账号池状态，不会删除凭据或改变已绑定线路。

这与单官方账号模式和 BYOK 模式并存：不绑定账号池时，Provider 仍使用自己的隔离登录目录；填写 URL、Key 和模型通道时，仍由 BYOK 直接访问中转站。账号池的凭据格式必须来自对应官方 CLI 或官方登录流程，不能把任意网页 Cookie 当作 API Key。Grok 的 `~/.grok/auth.json` 可以直接导入（支持 `https://accounts.x.ai/sign-in`、`https://auth.x.ai::<client-id>` 和 `xai::api_key` 条目）；订阅条目会走 Grok CLI 会话代理，API Key 条目才走 xAI API。Codex 的 `auth.json` 可能依赖 keyring，Claude 的 OAuth 可能受系统 Keychain 影响；导入失败时应改用 Provider 卡片中的官方登录按钮。

Kimi 供应商同时支持两种模式：选择 **API** 时填写 Kimi Coding 的 OpenAI 兼容地址和 `KIMI_API_KEY`，选择 **官方 CLI** 时运行 `kimi login`。切换回官方 CLI 会清除该实例保存的 Kimi API 覆盖，避免登录成功后仍被旧 API Key 接管；Antigravity 当前只提供 `agy` 官方 CLI 登录，不显示未经验证的 API 模式。

需要让外部 Agent（例如 OpenAI 兼容客户端或 Anthropic 客户端）使用本地账号池时，在 **外部 Agent 网关** 中创建一个 Key。页面只在创建或轮换成功的结果中显示一次明文 Key；列表、状态和普通 settings RPC 永远只返回名称与创建时间。OpenAI 兼容 URL 使用 `.../byok-gw/openai/v1`，Anthropic URL 使用 `.../byok-gw/anthropic`。该 Key 只能访问本地账号池，不能访问服务器上的普通 BYOK 通道；撤销或轮换会立即使旧 Key 失效。服务器默认绑定回环地址，远程 Agent 需要将 Code Work 绑定到可达主机或通过 HTTPS 反向代理暴露，并自行限制网络来源。

账号池只在一次 HTTP 请求开始时选取账号；首个账号在响应体开始前遇到鉴权、限流、服务端错误或网络错误时，网关最多自动换用一个健康账号。已经产生的流式响应不会中途换号。遇到所有账号都失败、官方端点协议变化或需要 OAuth 刷新时，重新导入或通过官方 CLI 登录，不能把“账号已导入”当作真实调用已经成功。

## 内置 CLIProxyAPI 核心兼容入口

这里的兼容入口已经移到 Code Work Server 进程内，不需要安装、配置或启动外部 `cli-proxy-api` 程序，也没有 `binaryPath`、独立端口或子进程生命周期。**设置 → CLI 账号池与转发** 里的状态、模型目录和账号调度都由同一个服务器保存。

使用步骤：

1. 在 **本地官方账号池** 导入 Codex、Claude 或 Grok 的 `auth.json`、凭据 JSON 或 API Key；需要作为共享 BYOK 线路发布的账号，再在 `models` 数组（或 `model` 字段）声明模型。
2. 选择“轮询账号”或“优先用满当前账号”，按需停用、删除账号。
3. 点击 **一键接入供应商**（或高级设置中的“连接为共享线路”），为这组账号创建一个 BYOK 实例。服务器会把本地账号绑定为稳定的 `local:<实例>:<平台>:<模型>` 路由，并自动让已启用且有匹配账号的 Codex、Claude、Grok、OpenCode 实例使用这条线路；之后新导入的同类账号也会加入已接入线路。
4. 账号池后续变化会自动同步：导入、启停或删除账号后，该 BYOK 实例的模型目录（含会话模型选择器和团队模型绑定里看到的列表）随即更新，无需重新接入。已保存的团队绑定不受刷新影响，只要对应模型仍然可用。
5. 调用统计在 **用量** 页的"本地账号池调用"卡片中，按账号显示调用次数、失败次数、token（输入/输出）和最近使用时间。token 来自网关对流式响应的统计；统计持久化在服务器数据目录，重启后保留。Cursor 账号走 ACP 子进程、不经过网关，因此不计入。
6. 外部 OpenAI/Anthropic 客户端需要访问时，创建一次 **外部 Agent Key**，使用页面给出的 `/v1` 地址和一次性 Key。

当前兼容核心提供：`GET /v1/models`、`POST /v1/chat/completions`、`POST /v1/responses`、`POST /v1/messages`，以及 `/v0/management/auth-files`、`/auth-files/models`、`/auth-files/status` 和 `/routing/strategy` 的管理子集。`/v1/models` 默认返回 OpenAI 目录；带 `Anthropic-Version` 或 `claude-cli` User-Agent 时返回 Anthropic 目录。管理导入支持带 `.json` 文件名的原始 JSON（需包含 Code Work 支持的 `type`/`provider` 与模型声明）和 `multipart/form-data` 文件上传；凭据只进入服务器密钥存储，响应和日志不返回令牌。

当前实现使用“导入凭据”流程；尚未把上游 CPA 的完整 OAuth/device-flow、Gemini、Realtime/WebSocket、插件和全部 management API 暴露出来。需要这些能力时，请继续使用现有 BYOK 外部服务连接，并不要把“服务器运行中”当成真实模型调用成功的证明。

## 手机上远程管理

手机连接到同一个 Code Work 服务端后，可以在 **设置 → BYOK 模型服务** 中读取并操作服务端上的 BYOK 配置。移动端支持新增、编辑、启用或删除模型服务和模型通道，也支持模型发现、上下文窗口校准、余额查询、提示词模板、委派配置、委派提交与取消，以及 cursor-byok YAML 导入。

移动端只通过服务端 WebSocket RPC 操作配置：已保存的 API 密钥和余额 Token 不会回传到手机；编辑已有通道时将密钥字段留空即可保留服务端密钥。手机不负责启动桌面本机的进程或 SSH 环境，目标服务端必须已经运行并完成配对；配对后，项目、线程、文件、Git、终端、Provider 会话和 BYOK 状态仍由该服务端统一持有。

Provider 也可以在手机的 **设置 → Provider** 中管理：可切换任意已连接电脑，读取驱动状态、版本和模型，编辑 Codex、Claude、Cursor、Grok、Kimi、Antigravity、OpenCode 的实例参数，启停实例，新增或删除自定义实例，并远程刷新、安装或更新服务端 CLI。未知驱动不会被手机覆盖，原配置会按原样保留。

## 在项目线程中审查代码

在绑定项目工作区的普通模型服务文本线程中，模型可以使用只读工具读取文件、查看 Git 状态和审查差异。要求模型审查仓库时，它会先读取实际代码证据，不再因为使用模型服务里的模型而提示“没有项目代码或仓库路径”。终端执行和文件写入仍遵循现有审批边界，不会自动绕过权限控制。

## 看懂运行时状态

- **可用**：驱动可以被任务选择。
- **降级**：驱动存在，但部分能力尚未准备好。查看 Provider 配置或展开技术详情排查原因。
- **不可用**：驱动未启用或暂时无法连接。回到 **供应商** 检查状态与配置。

## 管理模型通道

“模型通道”是一个模型 API 连接。你可以添加多个通道，例如为不同厂商分别配置不同的 URL 和模型。新增或编辑通道会在弹窗中完成，不会撑开当前 Provider 页面。已保存的 API 密钥不会在页面中回显；编辑已有通道时，留空即可保留原密钥。

每个通道还可以填写可选的“分组名称”。页面把所有中转铺成并列的卡片，不按分组折叠：同一分组且使用同一 Base URL 的模型会归在同一个中转下，每张卡片依次显示分组名称、中转 Base URL 和模型通道，点击卡片可在弹窗中查看模型、上下文窗口、协议、密钥状态和管理操作。留空的通道会显示在“默认分组”，便于逐步整理既有配置而无需重新添加模型。

中转连接头会集中显示协议、脱敏的密钥状态和模型数。已保存连接的“发现模型”只在这里出现一次，发现结果也会显示在同一个中转下；你可以勾选多个结果并添加到该连接，不需要为每个已有模型重复发现。只有点击该按钮时才会请求模型目录。

新增通道时同样可以使用“发现模型”读取当前草稿端点的公开模型目录。勾选一个模型会回填当前表单，可细调后再保存；勾选多个模型则用“添加所选 N 个模型”一次性全部入库，连接信息（协议、URL、密钥、分组）沿用表单当前值，不必逐个重复添加。

在中转详情卡片中可以对单个模型测速，也可以一键依次测试该中转的全部模型。测速结果按模型持久化；如果上游返回生成 token usage，页面会分别显示总生成 TPS 和正文 TPS，否则会明确标记“估算”，避免把可见文本估算值误认为供应商计费 token。独立测速请求带有固定输出上限，不会因为模型默认输出预算过大而把测速拖成长任务。

### 自动匹配上下文窗口

在已保存中转的连接头点击“自动匹配上下文”，系统会对这个中转连接的模型目录进行一次查询，并按模型 ID 使用其中明确返回的窗口。中转没有返回窗口信息时，系统会使用内置模型目录作为回退。中转明确返回的窗口视为当前渠道能力；内置目录只会收敛明显过大的值，不会覆盖用户主动设置的更小窗口。

中转明确返回的窗口优先于内置目录，因此同一模型经由不同中转提供时会按实际能力配置。内置 DeepSeek 模板使用 `deepseek-v4-flash` 和 `deepseek-v4-pro`，默认上下文窗口均为 `1,000,000`；如果你已经把窗口手动限制为更小值，内置目录匹配会保留该限制，避免自动校准偷偷放大上下文。API 密钥只在服务器端用于查询，不会返回到页面；如果中转不支持模型目录、请求失败且内置目录也没有对应信息，现有上下文窗口会保持不变。

## 余额与用量看板

余额看板会查询每个已保存模型通道可用的余额接口。官方 DeepSeek 通道的 Base URL 使用 `https://api.deepseek.com/...` 时，看板会通过 DeepSeek 的官方余额接口读取余额；自定义中转或其他域名不会被当作 DeepSeek 官方端点，避免把密钥发送到错误的供应商。

## 技术详情

运行时卡片中的“查看技术详情”用于排查问题，里面包含驱动 ID、运行时 ID、已验证能力和诊断原因。日常使用时只需关注状态和页面上的下一步按钮。
