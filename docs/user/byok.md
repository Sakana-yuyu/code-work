# BYOK 与委派

BYOK 让你把自己的模型 API 端点接入 Code Work，并在委派任务中选择这些模型。

## 使用顺序

1. 在 **设置 → 提供商** 中启用或选择 **Cursor BYOK**。
2. 在 **设置 → BYOK** 中添加模型通道。每个通道可以使用不同的厂商、Base URL、API 密钥、协议和模型 ID。
3. 在 **设置 → 运行时** 中确认 BYOK 显示为“可用”。这里仅说明驱动是否就绪，不会创建任务或修改模型配置。
4. 在 **设置 → 委派** 中选择已就绪的 BYOK 驱动，填写任务后创建委派。

## 在项目线程中审查代码

在绑定项目工作区的普通 BYOK 文本线程中，模型可以使用只读工具读取文件、查看 Git 状态和审查差异。要求模型审查仓库时，它会先读取实际代码证据，不再因为使用 BYOK 模型而提示“没有项目代码或仓库路径”。终端执行和文件写入仍遵循现有审批边界，不会自动绕过权限控制。

## 看懂运行时状态

- **可用**：驱动可以被任务选择。
- **降级**：驱动存在，但部分能力尚未准备好。查看 Provider 配置或展开技术详情排查原因。
- **不可用**：驱动未启用或暂时无法连接。回到 **提供商** 检查状态与配置。

## 管理模型通道

“模型通道”是一个模型 API 连接。你可以添加多个通道，例如为不同厂商分别配置不同的 URL 和模型。新增或编辑通道会在弹窗中完成，不会撑开当前 Provider 页面。已保存的 API 密钥不会在页面中回显；编辑已有通道时，留空即可保留原密钥。

每个通道还可以填写可选的“分组名称”。页面会按“分组名称 → 中转 Base URL → 模型通道”显示：同一分组且使用同一 Base URL 的模型会归在同一个中转下。分组默认折叠，标题会显示其中的 Base URL；展开后每个中转显示为卡片，点击卡片可在弹窗中查看模型、上下文窗口、协议、密钥状态和管理操作。留空的通道会显示在“默认分组”，便于逐步整理既有配置而无需重新添加模型。

中转连接头会集中显示协议、脱敏的密钥状态和模型数。已保存连接的“发现模型”只在这里出现一次，发现结果也会显示在同一个中转下；你可以勾选多个结果并添加到该连接，不需要为每个已有模型重复发现。只有点击该按钮时才会请求模型目录。

新增通道时同样可以使用“发现模型”读取当前草稿端点的公开模型目录。发现完成后，在搜索弹窗中勾选一个模型并使用它回填当前表单；每次点击“添加通道”只会保存一个模型通道。

### 自动匹配上下文窗口

在已保存中转的连接头点击“自动匹配上下文”，系统会对这个中转连接的模型目录进行一次查询，并按模型 ID 使用其中明确返回的窗口。中转没有返回窗口信息时，系统会使用内置模型目录作为回退。该操作是一次主动校准：只要诊断到的窗口与当前值不同，就会更新当前值，包括把历史的 `128K` 修正为 `1M`。

中转明确返回的窗口优先于内置目录，因此同一模型经由不同中转提供时会按实际能力配置。内置 DeepSeek 模板使用 `deepseek-v4-flash` 和 `deepseek-v4-pro`，默认上下文窗口均为 `1,000,000`；历史 `deepseek-chat`、`deepseek-reasoner` 配置在诊断时也会校准为 `1,000,000`。API 密钥只在服务器端用于查询，不会返回到页面；如果中转不支持模型目录、请求失败且内置目录也没有对应信息，现有上下文窗口会保持不变。

## 余额与用量看板

余额看板会查询每个已保存模型通道可用的余额接口。官方 DeepSeek 通道的 Base URL 使用 `https://api.deepseek.com/...` 时，看板会通过 DeepSeek 的官方余额接口读取余额；自定义中转或其他域名不会被当作 DeepSeek 官方端点，避免把密钥发送到错误的服务商。

## 技术详情

运行时卡片中的“查看技术详情”用于排查问题，里面包含驱动 ID、运行时 ID、已验证能力和诊断原因。日常使用时只需关注状态和页面上的下一步按钮。
