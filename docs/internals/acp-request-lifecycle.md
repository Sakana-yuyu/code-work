# ACP 请求生命周期

本模块覆盖标准 ACP 的权限、工具取消、会话关闭和进程断开。Cursor、Kimi 与通用 ACP 共用 CursorAdapter；Grok 使用同一运行时、协议与权限选择函数。目录安装、认证、模型推理、工具实际副作用是独立能力，不能用生命周期夹具替代真实 Agent 验收。

## 原生权限与工具身份

`selectAcpPermissionOptionId` 按上游 option.kind 选择 allow_once、allow_always 或 reject_once，原样回传 optionId，不假设 ID 的拼写。会话授权未广告时只能退到本次授权；没有可匹配选项则回传 cancelled，并把审批结果记为取消。

权限请求中的 toolCallId 不证明工具执行。运行时仅在根会话登记此前未知的审批身份；允许、拒绝或取消后，只有字段完全为空的匹配权限终态才被消化。真实工具更新、输出、不同身份或不匹配状态继续进入既有工具流。已出现真实执行更新的身份不再按纯审批过滤；下一回合清理仅审批登记，旧历史不重写。

客户端取消可能收不到上游工具终态。运行时对已展示的 pending/inProgress 工具补 failed，并清理追踪；未展示的审批身份不造出新工具行。这只表示客户端停止等待，不保证命令或文件操作已经撤销。

## 关闭与断开

关闭不启动新会话。仅对已经建立且广告 sessionCapabilities.close 的会话发送 session/close，等待上限为 5 秒；没有能力广告直接释放本地资源。错误或超时仍完成本地收尾，发布异常 session.exited；公共 Ingestion 将原因保存为错误活动，普通退出保持原有静默行为。

协议同时监视输入流结束与子进程退出码，按首次终止结算一次，关闭输出队列并结束待定 RPC。Windows 包装层可能在进程退出后保持管道打开，因此不能只依赖 EOF。连接已断开后再次请求立即失败，避免新请求入队后无限等待。

审批和用户输入的等待可中断，发布请求与终态结算处于同一保护流程。终态通过待定身份删除保证只发布一次；断线取消审批、清空输入，不能把中断当成允许。Adapter 发布失败回合与可恢复异常退出，释放本地会话；迟到回应由既有会话/请求身份校验拒绝。Grok 的普通 JSON-RPC 请求失败仍保留可用会话，断开才结算整回合并释放，避免额度错误破坏后续重试。

## 验证和回滚

定向测试包含原生 ID、缺失选项、权限身份和真实执行、取消终态、关闭能力/错误/超时、输入流未结束时退出、断开后的新请求和异常退出投影。Windows 子进程回归在收到审批或用户输入事件后，仅终止该夹具启动时记录的 PID；等待现有协议和回合事件，不按进程名称清理或用定时退出猜测状态。

本模块无数据库迁移。撤回对应模块提交即可恢复之前的运行行为，已经保存的错误活动保留，不删除账户、会话历史或安装目录。真实 CLI、多端设备与本地/远程/relay/tunnel 各自登记结果；这些协议和 Adapter 检查不构成全部 44 入口通过。
